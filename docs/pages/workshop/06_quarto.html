10  Create and render a reproducible Quarto report

Hands-on · Quarto

10.1 Introduction

In this activity, you complete and render a short report that reads the summary written by your pipeline. The report is partially completed: its methods are written, and you add the confidence interval, an interpretation, and the provenance fields. By the end, you should be able to explain where each number in the report came from and what a reader needs to recreate it.

You need the meta-summary.csv file from the targets activity.

Get back on track

If you arrived late, lost your session, or broke a working file, run this from the project root in the R Console. It selects the full dataset, backs up your working pipeline in workspace/, and rebuilds the summary with the reference pipeline. Any report edits you have already made are kept.

withr::with_dir(
  here::here(),
  source("pipelines/recover_workshop.R")
)

After recovery, start the report exercise at Step 1. If Quarto reports an error, look for the first error and the reported line or chunk in report.qmd.

10.2 Step 1: copy and render the template

Copy and render your report using the code below. Run the same render command after each edit. If you want to restart from the template, rename your existing workspace/report.qmd in the Files pane before running this block.

withr::with_dir(
  here::here(),
  source("pipelines/workshop_support.R")
)
use_workshop_book_outputs()

dir.create("workspace", showWarnings = FALSE)
report <- here::here("workspace", "report.qmd")
if (!file.exists(report)) {
  stopifnot(file.copy("pipelines/exercise/health_wellbeing_report.qmd", report))
}
render_workshop_report()

Next, open the report.html. If you started from the template, the pooled estimate appears along with three TODO markers.

browseURL(
  here::here("workspace", "report.html")
)

10.3 Step 2: read the report source

Allow up to 10 minutes for this activity.

Open workspace/report.qmd in RStudio.

file.edit(
  here::here("workspace", "report.qmd")
)

The pipeline performs the analysis, while the report explains its methods and interprets the saved result. Because the report never retypes a number, rerunning the pipeline and rendering again updates every value.

10.4 Step 3: complete the three gaps

The Results section reports two 95% intervals that answer different questions:

  • The confidence interval describes uncertainty in the average association across studies. It usually narrows as studies are added.
  • The prediction interval describes where the true association in a new, comparable study is likely to fall under the model. It adds the between-study variance, \(\tau^2\), so it stays wide when the studies differ.

I² is the percentage of variation in the study estimates that is due to between-study heterogeneity rather than sampling error. Use these definitions to write TODO 2 in your own words.

Edit workspace/report.qmd and save it.

  • TODO 1, in Results: report the confidence interval using inline R code, following the pattern for the pooled correlation.
  • TODO 2, in Results: explain how the prediction interval and confidence interval answer different questions.
  • TODO 3, in Provenance: add list items for the dataset pin version and the pipeline script MD5.

Render the report again after updating the report.qmd file:

render_workshop_report()
browseURL(
  here::here("workspace", "report.html")
)

Solutions are below:

Solution to TODO 1

Replace the sentence about the pooled correlation and the TODO 1 paragraph with:

The pooled correlation was `r sprintf("%.3f", result$pooled_r)` with a
`r sprintf("%.0f%%", 100 * result$confidence_level)` confidence interval
from `r sprintf("%.3f", result$ci_lower)` to
`r sprintf("%.3f", result$ci_upper)`.
Example for TODO 2

Your wording can differ. For example:

The confidence interval describes uncertainty in the average association.
The prediction interval describes plausible true associations in a
comparable setting under the model.
Solution to TODO 3 
-   Dataset pin version: `r result$data_version`
-   Pipeline script MD5: `r pipeline_md5`

The completed reference report is pipelines/health_wellbeing_report.qmd. If you are stuck, compare your copy with it.

file.edit(
  here::here("pipelines", "health_wellbeing_report.qmd")
)

10.5 Step 4: render again and check the numbers

Reload report.html in your browser. Then compare its values with the summary file:

summary_csv <- read.csv(
  here::here(workshop_output_dir(), "meta-summary.csv")
)
summary_csv[, c("data_version", "studies", "pooled_r", "ci_lower", "ci_upper")]

Run this code to render the report and open it in your browser.

render_workshop_report()
browseURL(
  here::here("workspace", "report.html")
)

An approved HTML report can be served from a project site or attached to a release. Before sharing, review the report for any content that came from data with reuse conditions. The report source, versioned analysis code, metadata, and environment record help others understand how the published HTML was made.

10.6 Publishing and journal formats

Quarto extensions add formats and templates for particular publishing workflows. Browse the Journal Articles extension listing and find a format relevant to your field. Examples include:

Extension Article style or publisher
apaquarto American Psychological Association, seventh edition
elsevier Elsevier journals
plos Public Library of Science
jss Journal of Statistical Software

Open an extension’s repository to check its supported formats, required software, author metadata, and usage instructions. Compare the template with the target journal’s current submission guidance.

To try one, create a separate article directory and start from the Elsevier template:

rm -rf /home/rstudio/health-wellbeing-article
mkdir -p /home/rstudio/health-wellbeing-article
cd /home/rstudio/health-wellbeing-article
quarto use template quarto-journals/elsevier --no-prompt

The template supplies an example QMD, bibliography, and extension files. Elsevier supports elsevier-html and elsevier-pdf; the PDF format also requires a LaTeX installation.

Open the downloaded Elsevier template file:

elsevier_path <- here::here("health-wellbeing-article", "health-wellbeing-article.qmd")
file.edit(
  elsevier_path
)

And we can render this document as a PDF.

system2("quarto", c("render", shQuote(elsevier_path), "--to", "elsevier-pdf"))

browseURL(
  here::here("health-wellbeing-article", "health-wellbeing-article.pdf")
)

Extensions are stored locally in _extensions/. Include that folder with the article source in Git. For a release, record the Quarto and extension versions alongside the R package versions in renv.lock. See the Quarto guidance on installing and versioning extensions (Quarto, n.d.b).
