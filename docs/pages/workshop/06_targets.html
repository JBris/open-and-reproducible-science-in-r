10  Reproducible analytical pipelines

50–68 minutes · targets

10.1 Introduction

We will run a targets pipeline that reads a specified HealthWellbeing version, pools the study correlations, and writes a summary for the report. By the end of these 18 minutes, you should be able to trace the summary back to its input and predict what rebuilds when you select another version.

You need Git and box, pins, targets, and meta in your workshop environment. The dependency graph also uses visNetwork. Start with your Git checkout, local board, and version selection file. Your instructor can share a prepared board and summary for comparison. Dataset storage and versioning

10.2 Inspect the pipeline

The script is pipelines/_targets_health_wellbeing.R. Open it in your editor and follow the data dependencies in this order.

version_file -> data_version -> dataset_file -> studies -> fit
fit, data_version -> result -> summary_file

We mark the selector, pinned RDS, and summary CSV as file targets. At fitting time, the pipeline records the Git revision, the script checksum, and whether the script has local changes. If you work with local edits, keep a copy of that script to reproduce the fit.

The model uses the raw Pearson correlations and study sample sizes. Meta transforms each correlation to Fisher’s z scale and pools the effects with a random-effects model. We use restricted maximum likelihood (REML) to estimate between-study variance and the Hartung–Knapp method for the 95% interval. The summary converts the estimate and limits back to the correlation scale.

This model treats study summaries as independent and assumes their correlations address a comparable association. Differences in populations, measures, and sampling limit interpretation. This is a worked example of pooling reported effects from the supplied studies. Section 4.2.4 of the guide

10.3 Run the full dataset

In the R Console at the project root, load the commands used to inspect and run the pipeline. The store path keeps this exercise’s cache separate from other pipelines.

box::use(
  targets[tar_make, tar_outdated, tar_read, tar_visnetwork],
  utils[read.csv]
)
invisible(loadNamespace("visNetwork"))

workshop_dir <- file.path("outputs", "health-wellbeing")
pipeline_script <- file.path("pipelines", "_targets_health_wellbeing.R")
pipeline_store <- file.path(workshop_dir, "_targets")
selection_file <- file.path(workshop_dir, "analysis-data-version.txt")

Use the graph to predict which targets depend on the selector. If you’re using the PDF, follow the text diagram above.

tar_visnetwork(
  script = pipeline_script,
  store = pipeline_store,
  targets_only = TRUE,
  outdated = FALSE
)

10.5 Checkpoint

The full example combines 29 studies with a pooled correlation of about 0.36 and a 95% interval of about 0.31 to 0.41. The alternative input combines 18 studies. The selector and downstream analysis rebuild when it changes. If both fits use the same checkout, they record the same Git revision. After restoring the full selection and rebuilding, tar_outdated() should be empty.

The file outputs/health-wellbeing/meta-summary.csv now contains the full result. The fit stores its Git and software provenance. The report keeps those details when the pipeline reuses a fit. Use a clean pipeline store to check results in a changed environment. Reproducible reporting and publishing
