9  Build and execute a targets meta-analysis pipeline

Hands-on · targets

9.1 Introduction

In this activity, you complete and run a targets pipeline that reads the selected HealthWellbeing version, pools the study correlations, and writes a summary for the report.

The pipeline is partially completed: you fill in two short gaps rather than writing it from scratch. By the end, you should be able to trace the summary back to its input and explain which steps targets reruns, and why.

Work in your MyBinder session, after preparing the dataset versions. If you fall behind, the Get back on track step below restores a working pipeline so you can continue. Prepare the dataset versions

Get back on track

If you arrived late, lost your session, or broke a working file, run this from the project root in the R Console. It selects the full dataset, backs up your working pipeline in workspace/, then restores and runs the reference pipeline.

source("pipelines/recover_workshop.R")

After recovery, run Step 1 to set the paths and then skip to Step 4. You can also go straight to the Quarto report exercise.

9.2 The pipeline at a glance

A target is one named step whose result targets stores and tracks. When a target’s code mentions another target by name, it depends on that target. The analysis has four stages:

select input -> check studies -> fit meta-analysis -> write summary
Stage Numbered steps in the script Targets Your gap
Select input 1–3 version_file, data_version, dataset_file None
Check studies 4 studies None
Fit meta-analysis 5 fit TODO 1 connects studies to fit
Write summary 6–7 result, summary_file TODO 2 writes the summary file

The checked studies also feed a second output: the linear regression predictive model from the versioning demonstration. The summary records that model’s version.

check studies -> train and pin predictive model -> model version in the summary
Every target and its dependencies 
version_file -> data_version -> dataset_file -> studies -> fit
dataset_file, data_version -> data_provenance
studies, data_provenance, data_version -> predictive_model -> model_pin_files -> model_version
fit, data_provenance, data_version, model_version, pipeline_file -> result -> summary_file

version_file, dataset_file, and summary_file are file targets: targets tracks the contents of the selection file, the pinned RDS file, and the summary CSV. pipeline_file tracks the analysis script and its checksum.

The model uses the raw Pearson correlations and study sample sizes. meta transforms each correlation to Fisher’s z scale and pools the effects with a random-effects model. We use restricted maximum likelihood (REML) to estimate between-study variance and the Hartung–Knapp method for the 95% confidence interval of the pooled correlation. The summary converts the estimate and limits back to the correlation scale. It also records between-study heterogeneity and a 95% prediction interval, which the report lesson explains.

This model treats study summaries as independent and assumes their correlations address a comparable association. Differences in populations, measures, and sampling limit interpretation. This is a worked example of pooling reported effects from the supplied studies (Harrer et al. 2021, sec. 4.2.4).

9.3 Step 1: copy the workbook pipeline

Run this code. It loads the targets functions and copies the partially completed template to workspace/_targets.R, your own working copy. The copy is only made if it does not exist yet, so rerunning the chunk keeps your edits. Git ignores the workspace/ folder, so the supplied template stays unchanged.

source("pipelines/workshop_support.R")
use_workshop_book_outputs()

box::use(
  targets[tar_make, tar_network, tar_outdated, tar_read, tar_visnetwork]
)
invisible(loadNamespace("visNetwork")) # Load the graph display package quietly.

source("pipelines/workshop_support.R")
workshop_dir <- workshop_output_dir()
pipeline_template <- file.path(
  "pipelines", "exercise", "_targets_health_wellbeing.R"
)
pipeline_script <- file.path("workspace", "_targets.R")
pipeline_store <- file.path(workshop_dir, "_targets")

dir.create("workspace", showWarnings = FALSE)
if (!file.exists(pipeline_script)) {
  file.copy(pipeline_template, pipeline_script)
}

9.4 Step 2: run the pipeline before completing it

Open workspace/_targets.R in RStudio and read the numbered steps. Then draw the dependency graph and try to run the pipeline.

tar_visnetwork(
  script = pipeline_script,
  store = pipeline_store,
  targets_only = TRUE,
  outdated = TRUE
)
tar_make(script = pipeline_script, store = pipeline_store)
✔ skipped pipeline [288ms, 12 skipped]

Nothing connects result to summary_file and the fit step has thrown an error. The run stops at a TODO placeholder.

Solution to TODO 2

A file target returns the path of the file it wrote. targets then tracks the file’s contents and rebuilds it if the file changes.

On the first complete run, targets with new or changed inputs report that they completed. targets saves every result in the pipeline store, here outputs/health-wellbeing/_targets, and tar_read() loads a saved result without rerunning anything.

9.7 Step 5: run it again

Run the pipeline a second time and ask which targets are outdated.

tar_make(script = pipeline_script, store = pipeline_store)
tar_visnetwork(
  script = pipeline_script,
  store = pipeline_store,
  targets_only = TRUE,
  outdated = FALSE
)

Nothing runs, and no target is outdated. targets reruns a step only when its code, its upstream targets, or its tracked files change.

9.8 Checkpoint

Refer the bottom two steps of workspace/_targets.R. We have fitted a mixed-effect meta-analysis model, and written the results to a csv file: outputs/health-wellbeing/meta-summary.csv.

read.csv(file.path(
  "outputs", "health-wellbeing", "meta-summary.csv"
)) |> 
  dplyr::select(c("data_version", "data_scope", "data_filter", "pooled_r", "confidence_level", "tau2", "effect_scale", "tau_method", "meta_version")) |>
  dplyr::mutate(across(where(is.numeric), ~ round(.x, 3))) |> 
  tidyr::pivot_longer(
      cols = everything(),
      names_to = "metric",
      values_to = "value",
      values_transform = list(value = as.character)
    )
