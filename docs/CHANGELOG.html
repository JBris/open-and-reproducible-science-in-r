21  Changelog

21.1 1.0.0 - 2026-11-28

21.1.1 Added

  • Add the CARE Principles for Indigenous Data Governance to the FAIR lesson’s further reading.
  • Add a separate Docker Compose configuration for Memgraph, Memgraph Lab, and a read-only Memgraph MCP server.

21.1.2 Changed

  • Streamline MyBinder preparation and the opening Git exercise. Revise the lessons on computational environments, FAIR assessment, and data and model versioning to show the steps used in the workshop demonstrations.
  • Revise the targets, Quarto, and reproduction exercises to clarify the dependency graph, report provenance, and comparison of REML and DerSimonian–Laird estimates.
  • Configure RStudio to open the workshop project in the prepared environment when no project is active, and lock the rstudioapi dependency.
  • Refresh the published HTML book, PDF, search index, and sitemap.

21.1.3 Fixed

  • Use Knitr for the lessons with Bash examples and skip interactive dependency graphs in PDF renders.
  • Restore the CSS, JavaScript, and widget assets used by the published HTML.
  • Repair the links to the Correlations section and dataset preparation. Remove links to the retired export checklist and Git fork exercise.

21.2 0.9.0 - 2026-11-22

21.2.1 Changed

  • Recommend the Claude Code extension alongside the Codex extension in the VS Code workspace, and label the hook-test task for both.
  • Record the maintainer-accepted discrepancies in AGENTS.md so agent reviews do not report them again.
  • Remove the redirect pages for chapter addresses used before the 0.6.0 restructure, so pages/ holds only lesson sources.
  • Remove the CRANextra repository from renv.lock. No locked package comes from it, and renv’s check of that server could stall R sessions, including book renders.
  • Rebuild the published HTML book and PDF.

21.2.2 Fixed

  • Show the Massey University contact on the published contribution page.
  • Make clear that the opening Git activity compares the reference pipeline, the completed solution to the pipeline exercise.
  • Show the release image workflow status in the README so the badge covers both the RStudio and Binder builds.
  • Include the project-root .here file in the export checklist and link to the step that saves fair-assessment.rds before export.
  • Explain that versioned pins keep previous versions and skip identical writes by default.

21.3 0.8.0 - 2026-11-22

21.3.1 Changed

  • Describe the workshop archive through its concept DOI, which cites all versions and resolves to the latest one, in the opening, the archiving checkpoint, the README, and the draft plans.
  • Remove the unused R/dummy.R and pipelines/_targets_dummy.R placeholders, their mentions in the agent instructions, and the R/ copy in both images.
  • Write the FAIR lesson’s follow-up on saving assessment results for participants. It explains why to keep the run date and versions, and where to find and export the saved file.
  • List every root document rendered into the book in the agent instructions and the Quarto workshop skill.
  • Refresh the published FAIR lesson and PDF.

21.3.2 Fixed

  • Direct participants with a missing report to Step 1 of the Quarto exercise, because recovery no longer restores the report.
  • Mention the opening Git activity in the session overview. Drop the retrieval date from the notes for the commit-pinned teaching snapshot.
  • Update the simulated review record and the draft plan’s checklist to match the changes made since.
  • Use the coordinator’s Massey University address for conduct reports in the contribution guidelines.
  • Align the draft plan’s FAIR learning objective with the introduction and README.

21.4 0.7.0 - 2026-11-22

21.4.1 Changed

  • On GitHub releases, build and push the RStudio image before building the Binder image from the same revision.
  • Use FAIR for Research Software metrics when assessing the workshop’s Zenodo record in the archiving follow-up.

21.4.2 Fixed

  • Restore the full 29-study REML baseline during recovery and preserve participants’ report edits so they can complete the Quarto exercise.
  • Keep former workshop URLs and their section links working. Restore the homepage search links for Getting started and People and community.
  • Link the README directly to the published preparation and Quarto exercises. Explain which .Rproj to open in a local Docker session.
  • Document the .here marker and summary CSV path needed to rerender an unpacked report.
  • Pin the JSON-LD revision used by the FAIR assessment and link the workshop archive through its concept DOI.

21.5 0.6.0 - 2026-11-21

21.5.1 Added

  • Claude Code project instructions (CLAUDE.md), settings, subagents, lifecycle hooks, and image-publishing approval prompts alongside the existing Codex setup.
  • Add partially completed targets pipeline and Quarto report templates in pipelines/exercise/. Participants copy them to an ignored workspace/ folder, and lessons provide collapsed solutions and a recovery script.
  • Add pipelines/prepare_health_wellbeing.R, which prepares the versioned dataset inputs before the session and reuses matching versions when rerun.
  • Add a hands-on lesson on modifying the analysis and reproducing the results.
  • Add a supplementary synthpop exercise that pools the original and synthetic study summaries.
  • Add an AIMOS2026 attendee subagent for Claude Code and Codex. It critiques workshop material from a participant’s perspective without editing files.
  • Record a simulated attendee review of the workshop revision in draft/. Record the outcome of the selected fixes in the review.
  • Add prepared metadata and a reviewed JSON-LD record for the HealthWellbeing snapshot. Show the full record in the FAIR lesson and lock rfair and its dependencies.

21.5.2 Changed

  • Centre the FAIR lesson on dataset documentation with dataspice and assessment with rfair.
  • Restructure the workshop into the final 90-minute programme, with one lesson per segment: 40 minutes of concepts and demonstrations, 42 minutes of hands-on work, and 8 minutes of discussion. Merge Git and GitHub into the opening and move the fork, commit, and push practice to follow-up material.
  • Demonstrate vetiver with a supplementary predictive model in the data and model versioning segment. Add GitHub releases to the archiving segment.
  • Make MyBinder the single prepared participant environment, with no installation during the session.
  • Add explicit recovery for participant work and isolate book rendering from that work.
  • Teach selective rebuilding with an estimator change. Report heterogeneity, prediction intervals, and dataset and model provenance.
  • Connect the vetiver demonstration to a predictive model branch and document the bundled snapshot’s upstream MIT licence.
  • Present the FAIR segment as a demonstration that runs rfair live against the repository’s JSON-LD, served through jsDelivr, with a room question on access statements, introduce the pipeline as four stages, define confidence and prediction intervals before the report exercise, and start the archiving segment from the participant’s report.
  • Add a two-minute Git activity to the opening, in which participants read the public repository’s tags and history in MyBinder without cloning it. Participants now use the project already in their MyBinder session.
  • Remove 11 packages left in renv.lock after codebook was dropped (GPArotation, gridExtra, haven, labelled, likert, mnormt, psych, repr, reshape2, rmdpartials, and skimr), so renv::status() reports a consistent project.
  • Copy data/raw/ into the RStudio and Binder images, so MyBinder sessions include the teaching snapshot and its licence notice, and the recovery script works in a fresh session.
  • Align lesson titles, objectives, recovery wording, and the coordinator affiliation with the current programme, and update the agent instructions for the implemented exercises and the MyBinder copy without Git history.
  • Read the report’s pipeline summary relative to the project root, so reports render from the project root without an execution-directory option.
  • Revise the introduction, landing page, README, draft teaching plan, and page plan for the final programme.
  • Refresh the published HTML book and PDF for the revised programme.

21.9 0.3.0 - 2026-11-19
